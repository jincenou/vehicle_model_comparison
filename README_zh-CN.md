# 刚体资产模型对比实验

本仓库整理刚体资产实验的代码、冻结名单及评测规范。范围为 **100 个已冻结 nuScenes 场景中的 500 个资产：432 个车辆资产 + 68 个非车辆资产**，涵盖现有分类体系中的 11 类。

对比方法为：现有 pipeline、Asset Harvester、原版 TRELLIS、TRELLIS.2、Hunyuan3D 2.1、ReconViaGen v0.2、SplatAD、OmniRe、Street Gaussians（DriveStudio 实现）。人体任务不属于本仓库的实验范围。

## 当前发布内容

- `configs/`：500 个资产与 100 个场景的标识、计数和来源哈希；不复制原图、权重或生成资产。
- `evaluation/`：源视角数值指标、特征指标、相机和朝向约束，以及 34 项 CPU 回归测试。
- `research_snapshot/`：原生生成、重载校验、真实输入整理、场景训练与资产渲染的研究代码快照。
- `docs/`：数据和输入条件、环境及复现要求、各指标定义、已知限制。
- `provenance/`：原始代码与发布代码的哈希对应关系。

这是**实验进行中的代码发布**，不是最终论文指标结果。发布没有改变后台训练任务，也没有把本地大文件复制进仓库。

## 输入约定

外部生成模型使用 pipeline 的真实源图和 mask。ReconViaGen 使用已经确认属于训练输入的真实多视图，不引入 FLUX，不补入评测视图。场景方法使用其原生场景观测，必须披露额外监督。

现有 pipeline 的历史资产中，364 条记录为 `flux_plus_real`，136 条为 `flux_only`；因此不能把已有结果写成“所有方法都只使用相同真实输入”。需要严格等输入实验时，应另建并明确标注该消融，不能混用历史结果。

## 快速验证

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-eval.txt
python scripts/validate_release.py
python -m unittest discover -s evaluation -p 'test_*.py' -v
```

以上只验证发布文件和数值实现，不下载模型、不占用 GPU，也不自动开始指标批量计算。

## 实验顺序

1. 固定 100 场景、500 资产及已有输入划分，校验输入哈希。
2. 按原生流程生成或训练，记录真实输入、额外监督、版本、权重和随机种子。
3. 独立重载并渲染，排查文件损坏、透明或空白输出，保留失败记录。
4. 确认对象身份、语义朝向和坐标系；源视角指标还必须确认真实尺度、位姿、时间戳与相机。
5. 审核每种指标的适用条件。没有真实留出或合格几何参考时，明确记录不可测。
6. 在同一有效对象交集比较分数，同时报告各方法覆盖率、失败数和不能测的原因。

500 条名单已经冻结，不再按其他模型生成效果重新筛选。显示时转正、居中或缩放，不能冒充物理配准；禁止逐方法调姿态来迎合参考图。此前停止的非车辆提取修复分支未纳入本次发布流程。
